# 思辨场 v0.4 · 用讨论把概念弄懂

思辨场是一个学习应用：写下一个想弄懂的概念，和 AI 讨论、追问或辩论。讲清楚的要点会被点亮，结束后生成理解复盘，存进知识库，并按间隔提醒你回顾。

## 开始使用

1. 解压完整版本，确保已安装 Node.js 22 或更新版本。本项目无第三方依赖，不需要 npm install。
2. Windows 双击 `start.cmd`；其他系统在此目录执行 `npm start`。
3. 浏览器打开 http://127.0.0.1:4173 。
4. 默认是演示模式，可以直接体验完整流程（“机会成本”有完整示例，其他概念使用通用模板）。
5. 要使用真实 AI，进入“AI 连接”，填写服务商的 Base URL、模型 ID 和 API Key，点击“连接并测试”。测试会调用一次模型，可能产生少量费用。

## 学习流程

1. **开始学习**：写下概念，选择讨论方式。
2. **讨论准备**：AI 拆出理解这个概念需要掌握的 4 到 5 个要点，改写出适合讨论的题目，并设定 AI 角色。题目、要点和角色背景都可以修改。
3. **讨论现场**：
   - 顶部的要点清单会随讨论点亮，模型在每次发言后报告这一轮讲清楚了哪些要点（标记不显示给用户）。
   - 每条 AI 发言下面可以“追问这句”：没听懂、举个例子、我不同意、事实还是观点。
   - 卡住时点“给点提示”，只给思路，不给答案。
   - 第 3、6 次发言后会弹出小结卡，请你用自己的话说说现在的理解，AI 对照要点给反馈。也可以随时手动写小结。
4. **理解复盘**：逐条评估要点（已掌握 / 还模糊 / 没讲到），列出需要纠正的理解，出 3 道检验题。复盘只依据你本人的发言和小结。
5. **知识库**：每次复盘自动存成一张知识卡片，第一次复习在第二天。复习时先凭记忆做题，再看复盘，然后选“记得很清楚”（间隔按 1、3、7、14、30、60 天拉长）或“还有点模糊”（明天再来）。“从薄弱点再讨论一次”会把上次还模糊的要点交给 AI，让新的讨论从那里切入。

## 四种讨论方式

| 方式 | 形式 | 适合什么时候 |
| --- | --- | --- |
| 苏格拉底追问 | 一个 AI 不断追问，你来回答 | 刚接触概念，检查自己哪里没懂 |
| 圆桌讨论 | 三位不同学科背景的 AI 各自发言，你主持；可以“请下一位发言” | 想从多个角度理解同一个概念 |
| 反向讲解 | 你当老师，AI 扮演困惑的学生 | 已经有一定理解，检验能不能讲清楚 |
| 正反辩论 | 沿用 v0.3 的赛制：每方 1 到 4 席，真人与 AI 混编，环节可编排 | 概念有争议或有多种解释 |

正反辩论里，“追问这句”的解释显示在讲解助手面板中，不进入比赛记录，也不占用发言轮次。AI 辩手依然只以辩手身份发言，但被要求不得为了立场歪曲概念。

## 连接协议与边界

支持 Bearer 认证的文本 Chat Completions 接口。可以填写基础地址（自动追加 `/chat/completions`），也可以填写完整地址。外部服务要求 HTTPS；本机服务可以使用 HTTP。请求使用 `model`、`messages`、`stream:false`，读取 `choices[0].message.content`。原生 Anthropic、Gemini、Azure 专用认证与仅支持 Responses 的接口尚未适配。

讨论准备和理解复盘要求模型返回 JSON。服务端会容忍代码块包裹和前后多余的一句话，并校验字段；仍然解析失败时会提示重试，不会用模板顶替。较小的模型更容易出现这种情况。

当前为完整文本响应，不流式显示；90 秒超时。失败、截断与取消不会改变讨论进度。取消本地请求不保证服务商停止计费。

## 密钥与数据

API Key 仅保存在本机 Node 服务的会话内存中，不写入磁盘、浏览器存储、日志、讨论记录或知识库。服务只监听 127.0.0.1。点击“断开并清除密钥”或终止 Node 服务可清除密钥；仅关闭页面不会立即清除服务内存。

讨论、计划和知识库保存在本浏览器的 `sibian-v2` 记录中，不同设备不共享。v0.3 的比赛记录（`sibian-v1`）不会自动迁移。讨论记录和知识库都可以导出为 Markdown。

## 验证

`npm test`：适配器、提示词组装、要点标记解析、结构化输出校验、会话隔离、取消、来源标记，以及演示模式下“准备 → 讨论 → 小结 → 复盘 → 知识卡片 → 复习”的完整链路。使用模拟接口，不需要真实密钥。
`npm run check`：JavaScript 语法检查。

尚未使用真实服务商密钥进行外部端到端验证，也未评估具体模型的讨论质量。
