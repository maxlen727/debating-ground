# 思辨场

通过和 AI 讨论、追问、辩论，把一个概念真正弄懂，并把理解落盘、定期回顾。

写下想弄懂的概念，选一种讨论方式。讨论中讲清楚的要点会被点亮；结束后生成理解复盘，存成知识卡片，按间隔提醒你回顾。

团队协作请先读 [CONTRIBUTING.md](CONTRIBUTING.md)；使用 AI Agent 工作时，Agent 的规范在 [AGENTS.md](AGENTS.md)。

## 快速开始

需要 Node.js 22.18 或更新版本（直接运行 TypeScript 的服务端）。

```bash
npm install
npm run build    # 构建界面到 dist/
npm start        # 打开 http://127.0.0.1:4173
```

Windows 可以双击 `start.cmd`，它会在第一次运行时自动安装依赖并构建。

默认是演示模式，不需要网络和密钥就能走完整个流程（“机会成本”有完整示例，其他概念用通用模板）。要使用真实 AI，在“设置”里填写服务商的 Base URL、模型 ID 和 API Key。

### 开发

```bash
npm run server   # 终端一：本机服务（4173）
npm run dev      # 终端二：界面热更新（5173），/api 自动转发到 4173
npm run check    # 类型检查
npm test         # 测试
```

## 学习流程

1. **学习**：写下概念，选择讨论方式。
2. **准备**：AI 拆出 4 到 5 个要点，改写出适合讨论的题目，并设定角色背景。题目、要点、角色、辩论席位和流程都可以修改。
3. **讨论**：
   - 顶部的要点会随讨论点亮。模型每次发言后报告这一轮讲清楚了哪些要点（标记不显示给用户）。
   - 轻点任意一条 AI 发言，可以追问：没听懂、举个例子、我不同意、这是事实还是观点。
   - 卡住时点“给点提示”，只给思路，不给答案。
   - 第 3、6 次发言后会出现小结卡，请你用自己的话说说现在的理解；也可以随时手动写。
4. **复盘**：逐条评估要点（已掌握 / 还模糊 / 没讲到），列出需要纠正的理解，出 3 道检验题。只依据你本人的发言和小结。
5. **知识库**：复盘自动存成知识卡片，第一次复习在第二天。复习时先凭记忆做题，再看复盘；“记得很清楚”会把间隔拉长到 3、7、14、30、60 天，“还有点模糊”则明天再来。“从薄弱点再讨论”会把上次还模糊的要点交给 AI，让新讨论从那里切入。

| 讨论方式 | 形式 | 适合什么时候 |
| --- | --- | --- |
| 苏格拉底追问 | 一个 AI 不断追问，你来回答 | 刚接触概念，检查自己哪里没懂 |
| 圆桌讨论 | 三位不同学科背景的 AI 各自发言，你主持；可以“请下一位” | 想从几个角度看同一个概念 |
| 反向讲解 | 你当老师，AI 扮演困惑的学生 | 已经有些理解，检验能不能讲清楚 |
| 正反辩论 | 每方 1 到 4 席，真人与 AI 混编，环节可编排 | 概念有争议或有多种解释 |

正反辩论里，追问的解释由讲解助手在弹出面板里给出，不进入比赛记录，也不占用发言轮次。AI 辩手只以辩手身份发言，但不得为了立场歪曲概念。

## 项目结构

```
shared/      前端与服务端共用的类型和模式定义
server/      本机服务（Node 原生运行 TypeScript）：ai.ts 组装提示词、调用接口、校验输出；server.ts 托管界面并代理 API
src/         React 界面
  store.ts     全局状态与本地持久化
  actions.ts   学习流程的全部操作
  lib/         AI 调用入口、演示模板、赛制、间隔复习、导出
  screens/     学习、准备、讨论、复盘、知识库、设置
tests/       node:test 测试（服务端、提示词、流程）
```

界面按手机设计：底部导航，讨论页全屏，追问用底部操作面板，跟随系统切换浅色和深色。桌面浏览器里居中显示为一列。

## 连接协议与边界

支持 Bearer 认证的文本 Chat Completions 接口。可以填写基础地址（自动追加 `/chat/completions`），也可以填写完整地址。外部服务要求 HTTPS，本机服务可以用 HTTP。原生 Anthropic、Gemini、Azure 专用认证与仅支持 Responses 的接口尚未适配。

讨论准备和理解复盘要求模型返回 JSON。服务端会容忍代码块包裹和前后多余的一句话，并校验字段；仍然解析失败时提示重试，不会用模板顶替。

当前为完整文本响应，不流式显示；90 秒超时。失败、截断与取消不会改变讨论进度。取消本地请求不保证服务商停止计费。

## 密钥与数据

API Key 只保存在本机服务的会话内存中，不写入磁盘、浏览器存储、日志、讨论记录或知识库。服务只监听 127.0.0.1。“断开并清除”或停止服务会清除密钥。

讨论、准备内容和知识库保存在浏览器的 `sibian-v3` 记录里，不同设备不共享。v0.4 的知识卡片（`sibian-v2`）会在第一次打开时自动迁移。讨论记录和知识库都可以导出为 Markdown。

- 流式输出、多台设备的真人联网、自由辩论的抢话调度。
- 知识库跨设备同步与复习提醒推送。
