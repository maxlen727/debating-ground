# 产品原则

这些原则决定思辨场“做什么”和“不做什么”。遇到拿不准的设计问题时，回到这里。

## 1. 目标是学懂，不是练口才

思辨场的每个功能都要回答一个问题：它让学习者更懂这个概念了吗？辩论只是讨论的一种形式，用来逼出概念的关键点，而不是为了赢。

**所以**：复盘评价理解，不评价表达；AI 辩手可以坚持立场，但不能为了立场歪曲概念。

## 2. 一起想，不是拷问

直接给答案最省事，但学习者什么也没留下；可一个问题接一个问题地追，学习者又会觉得在被审问。AI 是一起把概念想明白的伙伴：拿出看法、例子和知识，让学习者有东西可以接、可以反驳，结论留给学习者自己得出。

**所以**：AI 先给再问，提问是工具，不是每一轮的任务；嘉宾之间会互相回应；学习者说对了就痛快承认，回答得短就举个例子；只在事实或概念说错时纠正，而且一句带过；思路提示只给方向，不给答案；小结卡要求学习者用自己的话说。改提示词时用 `npm run eval:prompts` 检查有没有退回到“拷问”。

## 3. 诚实地评估

学习者需要知道自己真实的掌握程度，而不是一份好看的报告。

**所以**：复盘只依据学习者本人的发言和小结；立场和价值判断不算对错，复盘只点评理由是否说清楚、有没有考虑反方；AI 请求失败时显示错误，不用模板顶替；演示内容明确标注为演示。

## 4. 知识要落盘、要回顾

讨论过的理解，如果不记下来、不回头看，几天后就会淡忘。

**所以**：每次复盘自动存成知识卡片；按间隔提醒回顾；复习时先凭记忆做题，再看复盘；可以从上次的薄弱点再讨论一次。

## 5. 尽量不需要信任我们

学习者的密钥和学习记录属于学习者自己。

**所以**：数据默认只存在本地；密钥尽量不经过我们的服务器（本机运行、安卓直连、自部署后端）；代码公开；不接第三方统计。详见[密钥与隐私](../guide/api-and-privacy)。

## 6. 为手机设计

学习者大多在手机上使用，常常是零碎时间、单手操作。

**所以**：主要操作放在屏幕底部；讨论页全屏；追问用底部操作面板；浅色和深色都要好用。
